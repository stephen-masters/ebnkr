# ebnkr

IBAN validation and formatting for JavaScript and TypeScript, checked against
ISO 13616-1 and the SWIFT IBAN Registry. It runs in browsers and in Node, and
has no runtime dependencies.

```js
import { validateIban } from 'ebnkr';

validateIban('GB29 NWBK 6016 1331 9268 19');
// { valid: true, iban: 'GB29NWBK60161331926819', countryCode: 'GB',
//   checkDigits: '29', bban: 'NWBK60161331926819' }

validateIban('GB29 NWBK 6016 1331 9268 1');
// { valid: false, error: 'wrong-length',
//   message: 'An IBAN for GB has 22 characters, but this one has 21.' }
```

## What it checks

An IBAN is valid only if every one of these holds, checked in this order. The
first that fails is the one reported:

| Error code | The check |
|---|---|
| `not-a-string` | The input is a string. |
| `invalid-characters` | It contains only ASCII letters, digits, whitespace and hyphens. |
| `invalid-format` | It starts with a two-letter country code and two check digits. |
| `unknown-country` | The country is in the SWIFT IBAN Registry. |
| `wrong-length` | It has the length the registry gives for that country. |
| `invalid-bban` | The account number (the BBAN) follows the country's structure in the registry. |
| `invalid-check-digits` | The check digits are not 00, 01 or 99, which ISO 7064 MOD 97-10 never produces. |
| `checksum-failed` | The ISO 7064 MOD 97-10 checksum comes out at 1. |

Letters are accepted in either case, and the paper format's spaces, hyphens,
tabs and no-break spaces are ignored. Nothing else is: punctuation, letters
from other scripts and digits from other scripts are all rejected. In
particular, characters that only *become* ASCII in upper case, such as `ß` and
the dotless `ı`, are rejected rather than converted.

The checksum catches every change to a single character of the account number
and every swap of two neighbouring digits or letters. The property tests check
that for every country in the registry.

A valid IBAN is one that is well formed. It doesn't tell you that the account
exists.

## API

| Function | What it does |
|---|---|
| `validateIban(input)` | Validates, and returns the parts of a valid IBAN or the reason it is not. Never throws. |
| `isValidIban(input)` | The same checks, returning `true` or `false`. Never throws. |
| `electronicFormat(iban)` | Removes separators and converts to upper case: `GB29NWBK60161331926819`. |
| `printFormat(iban)` | Groups of four, as ISO 13616-1 specifies: `GB29 NWBK 6016 1331 9268 19`. |
| `computeCheckDigits(countryCode, bban)` | The two check digits for a country and BBAN, for building an IBAN. |
| `registry` | The registry entries, keyed by country code: length, BBAN structure, and SEPA membership. |

The types `IbanValidation`, `ValidIban`, `InvalidIban`, `IbanErrorCode` and
`CountrySpec` are exported for TypeScript.

## Installing

The package isn't published to npm. To use it, build it and install the
result:

```bash
npm install
npm run build
npm pack                                # writes ebnkr-1.0.0.tgz
npm install ../ebnkr/ebnkr-1.0.0.tgz    # in the project that uses it
```

It is an ES module. In a browser, import `dist/index.js` from a
`<script type="module">`, or let your bundler resolve it.

## The registry data

`src/registry.ts` is generated by `scripts/build-registry.mjs` from the SWIFT
IBAN Registry. swift.com refuses automated downloads, so the script reads the
machine-readable copy that the [schwifty](https://github.com/mdomke/schwifty)
project (MIT licence) parses from SWIFT's release. That copy is pinned to a
tag and a SHA-256, and CI regenerates the file to check that it hasn't drifted.

Territories that SWIFT lists separately but whose IBANs carry another
country's code are left out. Åland uses `FI`; Jersey, Guernsey and the Isle of
Man use `GB`; the French overseas territories use `FR`.

## Developing

You need Node 22.18 or later; `.nvmrc` selects Node 26, the current LTS.

```bash
nvm use
npm install      # also installs the git hooks
npm test         # the tests, with Node's built-in runner
npm run check    # lint, type-check, 100% coverage, build and smoke test
```

## Changes from the 2011 version

The 2011 version was a single `ebnkr` global with a Jasmine 1.0 spec. Its
checks were a checksum and nothing else, so it accepted `"1"` and `"0001"` as
valid IBANs. It also stripped any punctuation without complaint, and threw on
`null`. This version replaces it entirely:

| 2011 | Now |
|---|---|
| `ebnkr.isValidIBAN(iban)` | `isValidIban(iban)`, or `validateIban(iban)` for the reason |
| `ebnkr.compactFormat(iban)` | `electronicFormat(iban)` |
| `ebnkr.mod97`, `toNumericForm`, `shiftFirstFourCharsToEnd` | Internal; `computeCheckDigits` covers the use for them |
